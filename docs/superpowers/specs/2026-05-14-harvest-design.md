# Harvest v0 — design

**Status:** draft — awaiting review before implementation
**Date:** 2026-05-14
**Modules:** `cctx/harvest.py`, `cctx/cli.py` (harvest subcommand)
**Pipeline position:** `Diagnosis → [Harvest] → ApplyResult list → Renderer`

## 1. Goal

`cctx harvest` closes the autopsy loop. `cctx autopsy` diagnoses a session and produces `Patch` objects — append-style rule text targeting `CLAUDE.md`. Without harvest, the user has to manually copy-paste those patches from the terminal. Harvest applies them: it reads each patch, checks whether the content is already present in the target file, and — after a confirmation prompt — appends new sections to the file. The output is an idempotent, copy-pasteable set of rules that grow `CLAUDE.md` with evidence-backed discipline entries, one session at a time.

v0 scope: `CLAUDE.md` only, append only, single-session and cross-session paths, preview + confirm by default, `--apply` to skip confirmation, `--dry-run` to print without writing. Editing or removing existing rules is out of scope.

## 2. Patch application algorithm

### 2.1 `Patch.unified_diff` format

`Patch.unified_diff` as generated by `cctx/recommender/claude_md.py` is an append payload — lines prefixed with `+` — with no `--- a/file` / `+++ b/file` / `@@ ... @@` diff headers. This is intentional (autopsy spec §2.7, §10). The harvest applier extracts the body text by stripping the `+` prefix from each line.

Extraction:

```python
def _extract_body(unified_diff: str) -> str:
    """Strip leading '+' from each line of an append-style diff payload.

    A line of '+' alone becomes a blank line. Lines not prefixed with '+'
    are passed through unchanged (defensive; should not appear in v0 templates).
    """
    lines = []
    for line in unified_diff.splitlines():
        if line.startswith("+"):
            lines.append(line[1:])
        else:
            lines.append(line)
    return "\n".join(lines)
```

Result for the retry-loop template:

```
## Retry discipline

If the same command or file operation fails twice with the same error, stop and
diagnose before retrying. Read the relevant file, check the full error message,
confirm paths exist. Try a meaningfully different approach — never repeat the
exact failing call a third time.
```

### 2.2 Idempotency fingerprint

The fingerprint is the first line of the extracted body that begins with `## ` (a level-2 heading). For all v0 templates this is the first line.

```python
def _fingerprint(body: str) -> str | None:
    """Return the first '## ...' heading in body, or None."""
    for line in body.splitlines():
        if line.startswith("## "):
            return line.rstrip()
    return None
```

Fingerprint examples from the three v0 templates:

| FindingKind | Fingerprint |
|---|---|
| `retry_loop` | `## Retry discipline` |
| `scope_creep` | `## Scope discipline` |
| `stale_context` | `## Context hygiene` |

### 2.3 Idempotency check

Search the existing target file content for the fingerprint heading using a line-anchored, case-sensitive regex:

```python
import re

def _already_present(content: str, fingerprint: str) -> bool:
    pattern = re.compile(rf"^{re.escape(fingerprint)}\s*$", re.MULTILINE)
    return bool(pattern.search(content))
```

Case-sensitive and full-heading match prevents `## Scope` from colliding with `## Scope discipline`. If the fingerprint is `None` (body has no `## ` heading — should not occur with v0 templates), treat the patch as not-present and proceed.

### 2.4 Apply algorithm

```
Given: patch: Patch, target_path: Path

1. body = _extract_body(patch.unified_diff)
2. fp   = _fingerprint(body)

3. If target_path does not exist:
     Create an empty file (touch). Proceed as "not present".

4. Read target_path content.

5. If fp is not None and _already_present(content, fp):
     Return ApplyResult(status=SKIPPED, message="already present: {fp}")

6. Append to target_path:
     - Ensure file ends with exactly one blank line before the new content.
     - Write body followed by a trailing newline.

7. Return ApplyResult(status=APPLIED, message="appended: {fp or patch.description}")
```

### 2.5 Atomicity

Harvest is append-only to an existing file, not a rewrite. For v0, write is a direct append:

```python
with target_path.open("a", encoding="utf-8") as fh:
    if content and not content.endswith("\n\n"):
        fh.write("\n" if content.endswith("\n") else "\n\n")
    fh.write(body)
    fh.write("\n")
```

Rationale: append on a CLAUDE.md file is a minimal-impact write. The file is human-edited plaintext under version control; the user is expected to have it tracked in git. A temp-file + rename approach is unnecessary complexity for an append-only operation on a file this size. The safety guarantee is: if append fails mid-write (disk full, permission denied), the OS write fails atomically at the syscall level and the partial line is recoverable from the file system. v1 can add a pre-apply `git add -p`-style checkpoint if users request it.

### 2.6 Non-`CLAUDE.md` patches (v0 filter)

`Patch.target_file` can theoretically be `.claude/rules/<slug>.md` per the autopsy spec. In v0, harvest filters to `CLAUDE.md` only:

```python
def _is_supported_target(patch: Patch) -> bool:
    return patch.target_file == "CLAUDE.md"
```

Unsupported-target patches are reported as `SKIPPED` with `message="target not supported in v0: {patch.target_file}"` and surfaced to the user in the preview summary. They are not silently dropped.

## 3. CLI surface

```
cctx harvest <session.jsonl>             # preview patches from single session
cctx harvest <project> --since N        # preview from cross-session aggregation
cctx harvest <session.jsonl> --apply    # apply without confirm prompt
cctx harvest <session.jsonl> --dry-run  # print diffs, exit 0, no write
cctx harvest --target-dir DIR           # resolve CLAUDE.md relative to DIR (default: cwd)
```

### 3.1 Mode truth table

| Flag combination | Behavior |
|---|---|
| *(default)* | Preview all patches → interactive confirm → write on yes |
| `--apply` | Preview all patches → write immediately (no confirm) |
| `--dry-run` | Print what would change → exit 0 (no write, no confirm) |
| `--apply --dry-run` | Error: mutually exclusive |

### 3.3 Path resolution for `CLAUDE.md`

`target_path = (target_dir or Path.cwd()) / patch.target_file`

`patch.target_file` is always a bare filename in v0 (`"CLAUDE.md"`). No path traversal is possible. If `--target-dir` is not supplied, the file is resolved relative to the user's current working directory at invocation time (standard shell convention). The resolved path is printed before any write so the user can verify it.

## 4. `ApplyResult` dataclass

```python
from __future__ import annotations
from dataclasses import dataclass
from enum import Enum
from pathlib import Path

from cctx.models import Patch


class ApplyStatus(str, Enum):
    APPLIED  = "applied"
    SKIPPED  = "skipped"
    ERROR    = "error"


@dataclass
class ApplyResult:
    patch:       Patch
    status:      ApplyStatus
    target_path: Path
    message:     str          # human-readable one-liner for the renderer
```

`ApplyResult` lives in `cctx/harvest.py` alongside `apply_patch` and `preview_patches`. It is not added to `cctx/models.py` — it is harvest-internal and has no use outside the harvest pipeline.

## 5. Module structure

### `cctx/harvest.py`

Public API:

```python
def apply_patch(patch: Patch, target_dir: Path) -> ApplyResult:
    """Apply a single patch to its target file in target_dir.

    Does not prompt. Callers are responsible for preview/confirm logic.
    Returns an ApplyResult regardless of outcome; never raises on file errors.
    """

def preview_patches(patches: list[Patch], target_dir: Path) -> list[ApplyResult]:
    """Compute what would happen if each patch were applied.

    Does not write. Returns a list of ApplyResult with status APPLIED (would apply)
    or SKIPPED (already present / unsupported target), suitable for dry-run display.
    """

def apply_patches(patches: list[Patch], target_dir: Path) -> list[ApplyResult]:
    """Apply all applicable patches in sequence. Returns results for all patches."""
```

Internal helpers (not exported):
- `_extract_body(unified_diff: str) -> str`
- `_fingerprint(body: str) -> str | None`
- `_already_present(content: str, fingerprint: str) -> bool`
- `_is_supported_target(patch: Patch) -> bool`

## 6. User interaction flow

### 6.1 Preview mode (default)

```
$ cctx harvest ~/.claude/projects/myapp/abc123.jsonl

cctx harvest — applying patches to /Users/bryan/Projects/myapp/CLAUDE.md

  Patch 1 of 2 — retry_loop
  ─────────────────────────────────────────────────────────────
  Target:  /Users/bryan/Projects/myapp/CLAUDE.md
  Status:  would append
  Evidence: Edit(src/foo.py) failed 3× between turns 12–16

  + ## Retry discipline
  +
  + If the same command or file operation fails twice with the same error, stop
  + and diagnose before retrying. Read the relevant file, check the full error
  + message, confirm paths exist. Try a meaningfully different approach — never
  + repeat the exact failing call a third time.

  Patch 2 of 2 — stale_context
  ─────────────────────────────────────────────────────────────
  Target:  /Users/bryan/Projects/myapp/CLAUDE.md
  Status:  already present (## Context hygiene) — skipping

Apply 1 patch to /Users/bryan/Projects/myapp/CLAUDE.md? [y/N]:
```

On `y`: apply and print `Applied 1 patch.` On `N` or Ctrl-C: print `Aborted. No changes made.`

### 6.2 `--apply` mode

Same preview display, no confirm prompt. Immediately prints `Applied N patches.`

### 6.3 `--dry-run` mode

Same preview display, but:
- Skipped patches show `would skip` instead of `already present ... — skipping`
- Would-apply patches show `would append`
- Exits with `Dry run complete. No changes made.` Exit code 0.

### 6.4 Zero-patches case

If autopsy produces no findings (or all patches are skipped), print:
```
No patches to apply. Session looks clean.
```
Exit 0.

### 6.5 Rich rendering

Each patch is rendered as a rich `Panel` with:
- Panel title: `Patch N of M — {finding_kind}` (color-coded: high severity = red, medium = yellow)
- Body: the diff lines rendered as a `rich.syntax.Syntax` block with `diff` lexer
- Footer line: evidence summary in dim text

Skipped patches are rendered in dim/grey with `[skip]` badge. The confirm prompt uses `rich.prompt.Confirm`.

## 7. Safety rules

1. **Print target path before writing.** The resolved absolute path of `CLAUDE.md` is always displayed before any write occurs. The user can abort.

2. **Create if missing.** If the target file does not exist, harvest creates it (empty file) and proceeds. No error.

3. **Never overwrite.** Harvest is append-only. It never truncates, never rewrites. Existing content is preserved verbatim.

4. **Idempotent.** Running `cctx harvest` on the same session twice produces the same CLAUDE.md. Duplicate patches are detected by fingerprint and reported as skipped.

5. **Errors are non-fatal per patch.** If one patch fails (e.g., permission denied on the file), the error is captured in `ApplyResult(status=ERROR, message=...)`, reported to the user, and harvest continues with the next patch. At the end, the user sees a summary of applied/skipped/errored counts.

6. **`--apply` + `--dry-run` is a hard error.** Checked before any I/O.

7. **Non-`CLAUDE.md` patches are reported, not silently dropped.** Skipped with status `SKIPPED` and an informative message.

## 8. Testing strategy

### `tests/test_harvest.py`

**`apply_patch` — happy path:**
- Patch applied to an empty file → file contains the extracted body text.
- Patch applied to a file with existing content → body appended after a blank-line separator.
- Returns `ApplyResult(status=APPLIED)`.

**Idempotency:**
- Patch applied to a file that already contains the fingerprint heading → `ApplyResult(status=SKIPPED)`, file content unchanged.
- Case-sensitive: `## Scope discipline` fingerprint does not match a file containing `## Scope Discipline` (different casing) — treated as not present and appended. (Validates exact-match behavior.)

**Fingerprint collision prevention:**
- File containing `## Scope` does not cause `## Scope discipline` patch to be skipped.

**Non-existent target:**
- `apply_patch` on a path that doesn't exist creates the file and applies the patch.

**Unsupported target_file:**
- Patch with `target_file=".claude/rules/foo.md"` returns `ApplyResult(status=SKIPPED, message="target not supported in v0: ...")`.

**`--dry-run` (via `preview_patches`):**
- Calls `preview_patches` instead of `apply_patches`; target file is not modified.
- Returns `APPLIED` status for patches that would be applied (without actually writing).

**Error handling:**
- Simulate a write error (read-only file) → `ApplyResult(status=ERROR)` returned, no exception raised.

**`apply_patches` multi-patch:**
- Session with two patches, one already present: returns two `ApplyResult`s (one `APPLIED`, one `SKIPPED`). File contains only the new section.

**CLI integration (smoke test):**
- Invoke `harvest` command via `CliRunner` with a fixture session JSONL → exit code 0, no exceptions.
- With `--dry-run`: exit code 0, target file not created.
- With `--apply --dry-run`: `UsageError` raised, exit code non-zero.

### Fixtures

Reuse existing `tests/fixtures/claude_code/` JSONL corpus. No new session fixtures needed for harvest tests — harvest tests use synthetic `Patch` objects directly (unit tests on `apply_patch`). The CLI smoke test can use `short-clean/` (zero findings → zero patches → "No patches to apply" path) or the retry-loop fixture once the autopsy fixtures land.

## 9. Out of scope (v0)

- **Editing existing rules.** Harvest only appends. Modifying or replacing an existing `## Retry discipline` block is out of scope.
- **Removing rules.** `cctx harvest --check` (memory hygiene audit) is a v1.x feature per the brief.
- **Non-`CLAUDE.md` targets.** `.claude/rules/<slug>.md`, `AGENTS.md`, `.windsurfrules`. Harvest v0 writes only to `CLAUDE.md`. Other patch targets are skipped with an informative message.
- **Interactive patch picker.** All applicable patches are presented in sequence; there is no checkbox UI to select individual patches. Per-patch `[y/N]` prompts are v1.
- **Backup files.** No `.CLAUDE.md.bak` or similar. The file is append-only and expected to be under version control.
- **LLM-assisted summarization.** All patch content is deterministic template text.
- **Cross-agent export.** `cctx harvest --emit cursor-rules` is a v3 feature per the brief.
- **`--until` flag.** Cross-session mode accepts `--since N` only. Date-range windowing is deferred.

## 10. Layering invariants

- `cctx/harvest.py` never imports `click` or `rich_click`. CLI concerns stay in `cli.py`.
- `cctx/harvest.py` never imports `anthropic`. No LLM calls.
- `cctx/harvest.py` never imports the diagnostician or recommender. It receives `list[Patch]` as input.
- The renderer (`renderers/terminal.py`) extension for harvest output receives `list[ApplyResult]` and renders it. It never calls `apply_patch` or `apply_patches` directly.
- `ApplyResult` is defined in `harvest.py` (harvest-internal). It is not added to `models.py`.

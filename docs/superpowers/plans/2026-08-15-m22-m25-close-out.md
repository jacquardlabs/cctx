## 3. Release mechanics

`pyproject.toml:45-52` declares `[tool.semantic_release]` with no `commit_parser` override, so the **default Angular parser** applies and the **squash subject becomes the release commit**. A non-conforming or non-bumping type produces no version bump, no CHANGELOG entry, and no PyPI publish — silently.

- **`fix:` → patch bump. C, A, B1 each cut their own patch release. This is expected**; do not merge them together to reduce release noise.
- **`refactor:` → no bump. D and B2 must produce no release.** Do not retitle them to `fix:` for tidiness — neither has a user-visible change.
- **`ci:` → no bump. E.** `infra:` is not an Angular type and is not in CLAUDE.md's list; it would parse as nothing. Use `ci:`.
- No PR edits `CHANGELOG.md` by hand — semantic-release generates it from the subject.
